0. How to read this spec

Every number here is a starting value meant to agree with every other number. Values marked † are tuning values, and a few plant-level figures are rounded (the steam generator section duty, for one). §1.1 is the canonical thermal power; everything else derives from it. Appendix C lists what Rev A4 corrected. The heat balance was computed with IAPWS-IF97 steam tables and the Fink–Leibowitz sodium correlations, with turbine losses set so efficiency lands between BN-600 and BN-800. Physics values sit inside the published ranges for BN-600, BN-800, Superphénix, PFR and EFR. It is not a licensing-grade design and doesn't need to be.

3. Reactor physics and kinetics

The simulation runs real-time 3D multigroup space-time kinetics (§3.7). Everything in §3.1–3.6 describes the core that model must reproduce.

3.1 Kinetics constants

β_eff = 360 pcm, Λ = 4.0 × 10⁻⁷ s, mean delayed neutron lifetime 10.7 s. Six groups blended for MOX (Pu-239, U-238 fast fission, U-235):

No xenon. Xe-135 barely absorbs fast neutrons, so there is no poison-out after a trip. Restarts are gated by thermal limits, investigation and paperwork instead. One small real effect does remain: Np-239 decaying to Pu-239 adds about +30 pcm over the week after shutdown (half-life 2.36 d). Include it in the estimated critical position.

3.7 Core physics model

Real-time 3D multigroup space-time kinetics: hexagonal-Z nodal diffusion, solved with the improved quasi-static method and coupled assembly by assembly to the thermal-hydraulics. Every value in §3.1–3.6, plus the peaking factors in §2.4, is a target the model must reproduce, not an input to it.

Why multigroup, not two-group. Two-group diffusion is the standard for light-water reactor simulators, where neutrons split cleanly into fast and thermal. A sodium fast reactor has almost no thermal neutrons, so its realistic equivalent is several fast energy groups.

What 3D adds in this core: a single rod moving tilts the flux and the thermocouple map; sodium voiding adds reactivity at the core centre but removes it in the outer rings; a blocked assembly changes local power; a gas bubble's reactivity depends on its path. Whole-core power response changes little, because a fast core is tightly coupled. That is also why real sodium fast reactor safety codes often still use point kinetics.

7.3 Bypass

Two-stage bypass on each turbine: HP bypass from main steam to cold reheat, and LP bypass from hot reheat to the condenser, each sized for 60% of turbine flow, quick-opening in ≤ 2 s on a turbine trip, with desuperheating. The condenser absorbs 60% bypass indefinitely at design cooling water; beyond that, condenser pressure rises about 1 kPa per extra 10% †. Bypass buys time. Every kilogram through it is output thrown away.

House-load operation: when the grid separates, one unit can run back to the plant's own house load (≈ 65 MWe) with the rest of its steam on bypass, while the other unit trips and the reactor runs back. Getting it right keeps the plant off its diesels (S-28).

12. Damage and degradation model

12.1 Thermal fatigue

Each monitored component has a wall temperature that chases its fluid: dT_w/dt = (T_fluid − T_w) / τ_w, with τ_w = L² / (2α) and α ≈ 4 × 10⁻⁶ m²/s for steel. The stress proxy is abs(T_fluid − T_w). Count half-cycles between turning points of that value, ignore ranges below 10 K, and charge D = 0.5 × (range / ΔT_ref)³ / N_ref per half-cycle.

What this does to play: slow, well-coordinated changes create tiny wall differences and cost almost nothing, while trips and sloppy coordination cost a lot. A crew that holds P/Q and the feed-to-sodium ratio tight can ramp faster than a sloppy crew without extra damage. The procedural ramp limit still applies either way.

14.2 Space-time kinetics in real time

The improved quasi-static method splits the flux into an amplitude that changes fast and a shape that changes slowly, so each part runs only as often as it needs to (§3.7).

Amplitude, every 0.1 s. Λ is 4 × 10⁻⁷ s, so explicit integration at 10 Hz is hopeless. Use the prompt-jump form with scaled precursors s_i = λ_i Λ C_i, which removes Λ entirely. Reactivity, β_eff and Λ come from the latest shape, weighted by the adjoint flux.

-- amplitude, once per 0.1 s tick: n is taken linear across the step, which keeps the
-- growth rate right at high reactivity (holding n at its old value runs 11% slow at 0.8 beta
-- and 22% slow at 0.9 beta; a fully implicit form errs the same amount the other way)
local num, den = q, BETA - rho
for i = 1, 6 do
  local x = lambda[i] * dt
  local e = math.exp(-x)
  local w = (1 - e) - (1 - e - x * e) / x
  num = num + s[i] * e + beta[i] * n * (1 - e - w)
  den = den - beta[i] * w
end
local n1 = num / den
for i = 1, 6 do
  local x = lambda[i] * dt
  local e = math.exp(-x)
  local w = (1 - e) - (1 - e - x * e) / x
  s[i] = s[i] * e + beta[i] * (n * (1 - e - w) + n1 * w)
end
n = n1

Initialise at steady state with s[i] = beta[i] * n. The form holds while ρ stays below about 0.9β. Above that, flag a prompt-critical excursion and hand over to a scripted core-damage event rather than integrating through it.

Shape, every 0.5–2 s. One implicit time step of the multigroup diffusion equations over the whole mesh, renormalised so shape and amplitude stay consistent.

14.4 Keeping it multiplayer

14.5 Performance guardrails

Simulate numbers, not parts; there is no moving fluid geometry anywhere. Build the turbine hall and SG building as modular, streamed instances. Run alarm logic on the server and send clients state changes only.

14.6 Persistence and reset

Plant condition persists per private server (OD-9). Between sessions it keeps the cycle day and burnup, fatigue usage for every component, failed, isolated and drained equipment, cold trap loading, LCO clocks and the sequence-of-events log. Public servers always start fresh.

The private server owner can reset from a settings panel. A reset needs typed confirmation, then runs a 60-second countdown announced to everyone on the server, and returns the plant to hot standby at beginning of cycle with every component as new †. Key the save on game.PrivateServerId, check game.PrivateServerOwnerId before allowing a reset, and version the save format so later spec changes can migrate old plants.
